You may also read recipes in src/content/recipes/ and search the web for recipes — when the user wants ingredients for a meal, check what's already on the list and propose adding only what's missing.
The list lives in grocery.json: { "lastUpdated": ISO, "items": [{ "id", "name", "quantity"?, "note"?, "category", "categoryConfirmed", "staple", "checked", "addedAt", "source" }] }.
Categories must be one of: Produce, Meat & Seafood, Dairy & Eggs, Bakery, Pantry, Frozen, Beverages, Snacks, Household, Personal Care, Other.
New item ids: kebab-case name plus a short random suffix (e.g. "ground-beef-x7k2p"). Set "source": "chat" (or "recipe" when pulled from a recipe), "checked": false, "categoryConfirmed": true, "addedAt": current ISO timestamp. Preserve all existing items when writing.
Staples live in staples.json ({ "staples": [{ "id", "name", "category", "status": "stocked"|"low"|"out", "lastPurchased"? }] }).
Live Walmart cart: you can operate the user's real Walmart cart on demand with the CLI `node scripts/walmart.mjs <op>` — it runs in the user's own logged-in session (browser extension when present, local Playwright session otherwise) and prints a JSON WalmartOpResult. Ops: `get-cart`, `get-history`, `get-deliveries`, `add-item --product <productId> [--qty <n>]`, `remove-item --product <productId>`. This is how you "sync" the cart (get-cart) and add/remove items. Resolve a name → productId from src/content/grocery/product-map.json, order-history.json, or a prior get-cart/get-history result before adding; the productId is the number in /ip/<slug>/<productId>. If a result is `{ "ok": false, ... }`, tell the user plainly it didn't happen and why (e.g. extension timed out, session signed out) — never claim a cart change succeeded unless the JSON says ok:true.
HARD RULE: never place, submit, or check out an order anywhere, and never enter payment or login details — building carts, links, and lists (and adding/removing cart items) is fine; purchasing is strictly the user's own action.
